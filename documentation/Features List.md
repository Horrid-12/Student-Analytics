> Current reality (updated 2026-10-11): login lands on a student `/onboarding` page (PRN/degree/division/practical-batch/semester capture + GitHub & LinkedIn profile linking). The site is a college-wide analytics dashboard whose eight tabs are **Overview, Onboarding, Students, Repositories, Leaderboards, Support, Settings, My Profile** (`auth.py:ALL_PAGES`) rather than the personal-portal structure above. The old **History, Issues and Verification pages no longer exist** (no routes, templates or nav entries). The per-student persona (My Dashboard/Analytics/Progress/Goals/Reports) is a future phase.
>
> Planned additions (2026-10-11): `/posts` LinkedIn-style feed (posts + likes, row 81), `/reports` per-class faculty reports with PDF/CSV export (row 79), `/certifications` (row 78), DSA boards (LeetCode/CodeChef/Codeforces) on `/leaderboards` (row 80), plus HackerRank and expanded stats cards on Overview (rows 82, 83) and stat columns on Students (row 84).

## Architecture Principle

The student portal should be treated as an authenticated boundary rather than simply another public page. Keep GitHub as the first data source while designing the student profile and analytics layer so future integrations such as HackerRank, LeetCode, CodeChef, Kaggle and certifications can be added without redesigning the entire system.
